# Laporan bug pengujian browser — Payment

- **Tanggal:** 26 Oktober 2026, pukul 14.09 WIB.
- **Lingkungan:** Next.js production build lokal, `http://localhost:3102`.
- **Alat:** Playwright MCP global melalui Chrome; interaksi UI dan request HTTP asli.
- **Hasil:** 9 pemeriksaan lulus, 1 alur payment terblokir. Pemeriksaan tambahan
  memastikan tombol bayar nonaktif saat keranjang kosong.
- **Scope laporan:** hasil pengujian; belum ada perbaikan source code pada tahap ini.

## PAY-001 — Checkout tidak dapat membuat pembayaran karena konfigurasi belum lengkap

| Atribut | Nilai |
| --- | --- |
| Prioritas | P1 — menghambat pengujian integrasi pembayaran |
| Status | RESOLVED — checkout dan delivery webhook otomatis sandbox melalui ngrok terverifikasi |
| Jenis temuan | Konfigurasi lingkungan; belum membuktikan cacat pada SDK Midtrans |
| Area | Checkout → `POST /api/payment` |
| Reproduksi | Terulang pada sesi MCP isolated dan browser bersama |

### Prasyarat

Server memakai konfigurasi lokal saat pengujian: `MIDTRANS_IS_PRODUCTION` efektif
bernilai `false` dan `APP_URL` belum diisi. Produk `Brown Sugar Signature`
tersedia dengan harga Rp18.000.

### Langkah reproduksi

1. Buka halaman utama aplikasi.
2. Tambahkan `Brown Sugar Signature` ke pesanan.
3. Buka keranjang, naikkan jumlah menjadi dua, lalu klik **Checkout**.
4. Pastikan total Rp36.000.
5. Isi nama `Playwright Test`; kosongkan nomor WhatsApp yang bersifat opsional.
6. Pilih **QRIS** dan klik **Bayar dengan Midtrans**.
7. Periksa respons `POST /api/payment` serta pesan pada halaman checkout.

### Hasil aktual

Endpoint mengembalikan **HTTP 503**:

```json
{
  "error": "Pembayaran tidak dapat diproses. Silakan coba lagi."
}
```

Pesan error tampil di checkout dan tombol bayar kembali aktif. Browser tidak
diarahkan ke Snap. Tidak ada transaksi pembayaran berhasil yang dapat digunakan
untuk menguji webhook sampai status `PAID`.

### Hasil yang diharapkan

Dengan konfigurasi sandbox lengkap dan valid, checkout membuat satu order,
mendapatkan token/URL Snap, dan mengarahkan pelanggan ke halaman pembayaran
Midtrans. Error konfigurasi tetap tidak boleh membocorkan kredensial ke browser.

### Penyebab yang terkonfirmasi

`getMidtransConfig()` pada
[`frontend/lib/payment/midtrans.ts`](../../frontend/lib/payment/midtrans.ts)
mewajibkan `APP_URL` berupa URL yang valid. Variabel tersebut belum tersedia
pada lingkungan yang diuji, sehingga validasi gagal sebelum create Snap dipanggil.
Penanganan error pada
[`frontend/app/api/payment/route.ts`](../../frontend/app/api/payment/route.ts)
mengembalikan respons generik HTTP 503 tersebut.

Pemeriksaan tambahan hanya menunjukkan key yang tersedia tidak berawalan `SB-`.
Kecocokan key dengan sandbox **belum terverifikasi**, sehingga hal ini merupakan
tindak lanjut konfigurasi, bukan penyebab kedua yang telah dibuktikan melalui
respons Midtrans. Nilai key tidak dicetak, dicantumkan, atau diubah.

### Dampak

- Pelanggan pada lingkungan ini tidak dapat melanjutkan pembayaran dari checkout.
- Pengujian redirect Snap, pembayaran sandbox, webhook nyata, dan perubahan status
  ke `PAID` belum dapat diselesaikan melalui browser.
- Hasil pengujian UI yang lulus tidak cukup untuk menyatakan integrasi payment
  end-to-end siap digunakan.

### Rekomendasi dan verifikasi perbaikan

1. Isi `APP_URL` dengan origin aplikasi yang benar pada environment server.
   Untuk server pengujian laporan ini, gunakan `http://localhost:3102`;
   untuk webhook sandbox, gunakan origin HTTPS publik yang dapat diakses Midtrans.
2. Pastikan Server Key sesuai dengan akun dan mode sandbox tanpa membagikannya
   melalui chat, log, atau repository.
3. Restart server agar konfigurasi environment dimuat ulang.
4. Ulangi langkah reproduksi dan pastikan respons create payment berhasil serta
   browser berpindah ke Snap.
5. Selesaikan simulasi sandbox dan verifikasi webhook menghasilkan status `PAID`.

## Pemeriksaan lain dan batas pengujian

Filter kategori, tambah item, perubahan kuantitas, persistensi keranjang setelah
reload, total harga, validasi nama/telepon, pilihan metode bayar, penanganan error,
serta tidak adanya overflow horizontal pada lebar 390px telah diperiksa.
Tidak ditemukan uncaught JavaScript error pada pengujian terakhir.

HTTP 404 pada order ID yang tidak ada merupakan hasil uji negatif yang diharapkan,
bukan bug. HTTP 500 pada chunk JavaScript di server lama tidak muncul kembali
setelah menggunakan proses server baru; temuan tersebut tidak dihitung sebagai
bug source code yang masih terbuka.

Belum diuji melalui browser: pembayaran sukses, webhook sandbox nyata, refund,
expiry transaksi nyata, dan rekonsiliasi. Laporan ini tidak menyatakan bagian
tersebut lulus atau gagal.

## Tindak lanjut perbaikan — 26 Oktober 2026

Perbaikan yang sudah diterapkan:

- Menambahkan `APP_URL=http://localhost:3001` pada `.env` lokal yang diabaikan Git,
  tanpa mengganti kredensial existing.
- Memvalidasi format Server Key, kecocokan mode sandbox/production, protokol
  HTTP/HTTPS, dan kewajiban HTTPS untuk production sebelum membuat order.
- Menambahkan respons aman `503 PAYMENT_NOT_CONFIGURED` dengan pesan
  `Layanan pembayaran belum dikonfigurasi. Silakan hubungi kedai.` agar kesalahan
  konfigurasi tidak dianggap sebagai gangguan sementara yang cukup diulang.
- Menambahkan regression test untuk konfigurasi kosong/salah, Client Key yang
  tertukar, key yang tidak sesuai mode, serta URL production tanpa HTTPS.
  Test memastikan tidak ada order dibuat atau panggilan Midtrans saat konfigurasi
  ditolak. Key dan rincian error validasi tidak dikirim ke browser.

Validasi ulang: **11 test otomatis lulus**, typecheck dan build lulus, lint tanpa
error dengan 6 warning existing. Browser Playwright MCP isolated kembali
menunjukkan 9 pemeriksaan UI lulus dan create payment terblokir, kini dengan
respons `PAYMENT_NOT_CONFIGURED` yang sesuai. Bukti terbaru berada pada
`frontend/test-results/checkout/report.json` dan screenshot di folder yang sama.

**Kendala tersisa:** sebelum perubahan, pemeriksaan read-only ke Status API
sandbox menggunakan key existing mengembalikan HTTP 401. Tidak ada transaksi
dibuat pada pemeriksaan tersebut. Pengguna perlu mengganti `MIDTRANS_SERVER_KEY`
langsung pada `.env` dengan Server Key sandbox yang valid; jangan mengirimnya
melalui chat. Validasi format saja tidak membuktikan key masih aktif di Midtrans.
Bug ini belum ditandai selesai sampai redirect Snap dan webhook nyata berhasil
diverifikasi. Tidak ada perubahan source untuk menonaktifkan validasi pembayaran.

### Verifikasi setelah penggantian key sandbox

Pengguna mengganti key langsung di `.env`. Setelah server direstart, pengujian
Playwright dan pemeriksaan provider membuktikan:

1. `POST /api/payment` mengembalikan HTTP 201, token tersedia, dan browser berpindah
   ke domain `app.sandbox.midtrans.com`.
2. QRIS berhasil dimuat sebagai gambar 600px; total Rp36.000 sesuai dua item.
3. QR diuji melalui simulator resmi Midtrans `/v2/qris/index` hingga status PAID.
   Tidak ada dana nyata yang digunakan.
4. SDK Status API mengembalikan `settlement` dan signature provider tersedia.
5. Respons provider bertanda tangan dikirim ulang secara manual ke webhook lokal.
   Endpoint membalas HTTP 200 dan mengubah order dari PENDING_PAYMENT menjadi PAID.
6. Replay kedua membalas HTTP 200 dengan jumlah audit event tetap satu.
7. Browser yang sudah membuka halaman status menampilkan **Pembayaran berhasil**
   melalui polling, tanpa reload halaman.

Temuan konfigurasi PAY-001 ditutup. Delivery otomatis Midtrans ke server lokal
tidak diklaim lulus: webhook diuji dengan replay manual payload autentik, sedangkan
URL aplikasi masih localhost. URL HTTPS publik dan konfigurasi Payment Notification
URL di dashboard Midtrans diperlukan untuk menguji delivery otomatis.

Bukti lokal terbaru:

- `frontend/test-results/sandbox-payment/report.json`: checkout dan redirect Snap.
- `frontend/test-results/sandbox-payment/qr/report.json`: QR selesai dimuat.
- `frontend/test-results/sandbox-payment/webhook.json`: settlement, replay, dan idempotensi.
- `frontend/test-results/sandbox-payment/qr/snap.png`: QRIS sandbox.
- `frontend/test-results/sandbox-payment/paid.png`: status PAID pada browser aplikasi.

Ada satu console error CSP pada halaman Snap milik Midtrans; error tersebut tidak
menghalangi QR, simulasi pembayaran, atau perubahan status. Tidak ada uncaught
JavaScript error pada pengujian checkout. Kredensial tidak dicantumkan dalam laporan.

### Verifikasi delivery otomatis — 27 Oktober 2026

Tunnel ngrok diaktifkan dan Payment notification URL disimpan melalui dashboard
sandbox. Pada transaksi uji baru, simulator QRIS memicu notifikasi langsung dari
Midtrans ke endpoint publik; aplikasi menampilkan PAID tanpa reload dan tanpa
replay manual. Database menyimpan satu audit event PAID. Notification History
menampilkan status Completed untuk notifikasi Pending serta Settlement.

Bukti tersedia di `frontend/test-results/ngrok-webhook/automatic-webhook.json`,
`automatic-paid.png`, dan `notification-history.png`. Lihat [setup ngrok](../ngrok.md).
