# Laporan bug pengujian browser — Payment

- **Tanggal:** 26 Oktober 2026, pukul 14.09 WIB.
- **Lingkungan:** Next.js production build lokal, `http://localhost:3102`.
- **Alat:** Playwright MCP global melalui Chrome; interaksi UI dan request HTTP asli.
- **Hasil:** 9 pemeriksaan lulus, 1 alur payment terblokir. Pemeriksaan tambahan
  memastikan tombol bayar nonaktif saat keranjang kosong.
- **Scope laporan:** hasil pengujian; belum ada perbaikan source code pada tahap ini.

## PAY-001 — Checkout tidak dapat membuat pembayaran karena konfigurasi belum lengkap

| Atribut | Nilai |
| --- | --- |
| Prioritas | P1 — menghambat pengujian integrasi pembayaran |
| Status | OPEN — konfigurasi lokal belum lengkap |
| Jenis temuan | Konfigurasi lingkungan; belum membuktikan cacat pada SDK Midtrans |
| Area | Checkout → `POST /api/payment` |
| Reproduksi | Terulang pada sesi MCP isolated dan browser bersama |

### Prasyarat

Server memakai konfigurasi lokal saat pengujian: `MIDTRANS_IS_PRODUCTION` efektif
bernilai `false` dan `APP_URL` belum diisi. Produk `Brown Sugar Signature`
tersedia dengan harga Rp18.000.

### Langkah reproduksi

1. Buka halaman utama aplikasi.
2. Tambahkan `Brown Sugar Signature` ke pesanan.
3. Buka keranjang, naikkan jumlah menjadi dua, lalu klik **Checkout**.
4. Pastikan total Rp36.000.
5. Isi nama `Playwright Test`; kosongkan nomor WhatsApp yang bersifat opsional.
6. Pilih **QRIS** dan klik **Bayar dengan Midtrans**.
7. Periksa respons `POST /api/payment` serta pesan pada halaman checkout.

### Hasil aktual

Endpoint mengembalikan **HTTP 503**:

```json
{
  "error": "Pembayaran tidak dapat diproses. Silakan coba lagi."
}
```

Pesan error tampil di checkout dan tombol bayar kembali aktif. Browser tidak
diarahkan ke Snap. Tidak ada transaksi pembayaran berhasil yang dapat digunakan
untuk menguji webhook sampai status `PAID`.

### Hasil yang diharapkan

Dengan konfigurasi sandbox lengkap dan valid, checkout membuat satu order,
mendapatkan token/URL Snap, dan mengarahkan pelanggan ke halaman pembayaran
Midtrans. Error konfigurasi tetap tidak boleh membocorkan kredensial ke browser.

### Penyebab yang terkonfirmasi

`getMidtransConfig()` pada
[`frontend/lib/payment/midtrans.ts`](../../frontend/lib/payment/midtrans.ts)
mewajibkan `APP_URL` berupa URL yang valid. Variabel tersebut belum tersedia
pada lingkungan yang diuji, sehingga validasi gagal sebelum create Snap dipanggil.
Penanganan error pada
[`frontend/app/api/payment/route.ts`](../../frontend/app/api/payment/route.ts)
mengembalikan respons generik HTTP 503 tersebut.

Pemeriksaan tambahan hanya menunjukkan key yang tersedia tidak berawalan `SB-`.
Kecocokan key dengan sandbox **belum terverifikasi**, sehingga hal ini merupakan
tindak lanjut konfigurasi, bukan penyebab kedua yang telah dibuktikan melalui
respons Midtrans. Nilai key tidak dicetak, dicantumkan, atau diubah.

### Dampak

- Pelanggan pada lingkungan ini tidak dapat melanjutkan pembayaran dari checkout.
- Pengujian redirect Snap, pembayaran sandbox, webhook nyata, dan perubahan status
  ke `PAID` belum dapat diselesaikan melalui browser.
- Hasil pengujian UI yang lulus tidak cukup untuk menyatakan integrasi payment
  end-to-end siap digunakan.

### Rekomendasi dan verifikasi perbaikan

1. Isi `APP_URL` dengan origin aplikasi yang benar pada environment server.
   Untuk server pengujian laporan ini, gunakan `http://localhost:3102`;
   untuk webhook sandbox, gunakan origin HTTPS publik yang dapat diakses Midtrans.
2. Pastikan Server Key sesuai dengan akun dan mode sandbox tanpa membagikannya
   melalui chat, log, atau repository.
3. Restart server agar konfigurasi environment dimuat ulang.
4. Ulangi langkah reproduksi dan pastikan respons create payment berhasil serta
   browser berpindah ke Snap.
5. Selesaikan simulasi sandbox dan verifikasi webhook menghasilkan status `PAID`.

## Pemeriksaan lain dan batas pengujian

Filter kategori, tambah item, perubahan kuantitas, persistensi keranjang setelah
reload, total harga, validasi nama/telepon, pilihan metode bayar, penanganan error,
serta tidak adanya overflow horizontal pada lebar 390px telah diperiksa.
Tidak ditemukan uncaught JavaScript error pada pengujian terakhir.

HTTP 404 pada order ID yang tidak ada merupakan hasil uji negatif yang diharapkan,
bukan bug. HTTP 500 pada chunk JavaScript di server lama tidak muncul kembali
setelah menggunakan proses server baru; temuan tersebut tidak dihitung sebagai
bug source code yang masih terbuka.

Belum diuji melalui browser: pembayaran sukses, webhook sandbox nyata, refund,
expiry transaksi nyata, dan rekonsiliasi. Laporan ini tidak menyatakan bagian
tersebut lulus atau gagal.
